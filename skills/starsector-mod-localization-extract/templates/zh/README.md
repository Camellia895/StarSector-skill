# 译者工作区：把汉化后的产物放在本文件夹内

> 这个文件夹是给**译者（你）**用的。

## 怎么用

1. 上一级目录（`..\`）里有**待译清单**，每份是一个 JSON 数组，条目形如：

   ```json
   { "file": "data/hullmods/hull_mods.csv", "id": "...", "field": "desc",
     "line": 42, "en": "English text", "zh": "", "note": "上下文" }
   ```

2. **只填 `zh` 字段，其余字段一律不动**（改了会导致注入失败）。
   - 想表达"这条有意保留英文" → 让 `zh` 与 `en` **逐字相同**，注入器会自动跳过。
3. 填好后**另存到本文件夹**（不要覆盖上一级的原文件），**文件名保持一致**：

   ```
   worklist\
   ├─ 01_data.json          ← 待译（原件，别改）
   ├─ 02_structured.json
   ├─ 03_rules_missions.json
   ├─ 04_jar.json
   ├─ 05_misc.json
   ├─ worklist_index.json   ← 分片索引 + 条目数 + 被排除区域
   ├─ glossary.md           ← 基于本 mod 修正后的术语表
   └─ zh\                   ← 你填好的产物放这里
       ├─ 01_data.json
       ├─ 02_structured.json
       └─ ...
   ```

4. 一次只填一部分也可以：**只把填完的那几份放进本文件夹**，AI 会按已到位的最新的处理。

## 注意

- **不要改文件名**：AI 靠文件名把"已译产物"与"待译清单"配对。
- **不要删条目、不要加条目**：保持条目数与顺序；确实发现有遗漏，**告诉 AI 补进上一级的清单**
  （不要在 `zh\` 里自行新增，那样会与清单对不上）。
- 本文件夹的文件**不计入**"给译者的交付文件 ≤10 份"的限制——它属于回传产物。
- 术语若在翻译过程中有新决定，直接写进上一级的 `glossary.md`（或告诉 AI 更新它）。
