SSTLib (Starsector Mod API) 中文指南

远行星号（Starsector）模组开发接口文档
基于 com.fs.starfarer.api 源码注释整理 · 根包路径：SSTLib/starfarer.api/com/fs/starfarer/api/

1.总览与架构

SSTLib 是远行星号官方提供的模组开发 API（即 starfarer.api），位于 SSTLib/starfarer.api/com/fs/starfarer/api/ 目录下。它以 Java 接口（interface）为主，配合少量抽象基类，让模组作者无需接触游戏内部实现即可扩展游戏。

1.1 包结构总览

com.fs.starfarer.api
├── (根包)         核心入口：Global、ModPlugin、SettingsAPI、FactoryAPI
├── campaign/      战役层：星区、舰队、市场、对话、事件、规则
│   ├── ai/        舰队 AI 模块
│   ├── comm/      通讯与情报系统
│   ├── econ/      经济与市场
│   ├── events/    战役事件
│   ├── listeners/ 各类监听器（含输入监听）
│   └── rules/     规则与内存系统
├── combat/        战斗层：战斗引擎、舰船、武器、弹丸、舰船改装
│   └── listeners/ 战斗监听器（伤害、部署等）
├── characters/    角色：人物、技能、军官
├── fleet/         舰队成员数据
├── graphics/      图形：精灵图
├── impl/          官方参考实现（含大量可继承基类）
├── input/         输入事件
├── loading/       数据规格（武器、舰船、改装等 Spec）
├── mission/       任务模式
├── plugins/       通用插件接口（舰船系统、自动装配等）
├── ui/            用户界面组件
└── util/          工具类

1.2 两种游戏状态

API 区分两大游戏状态（见 GameState.java）：

💡 游戏状态

CAMPAIGN（战役）：大地图探索、经济、舰队管理。通过 Global.getSector() 访问。

COMBAT（战斗）：实时战斗。通过 Global.getCombatEngine() 访问。

TITLE：主菜单（也使用 CombatEngine 渲染）。

1.3 模组入口

模组通过 mod_info.json 中声明的 modPlugin 类被加载。该类需实现 ModPlugin 接口（推荐继承 BaseModPlugin）。

2.核心包 com.fs.starfarer.api

根包是整个 API 的入口，提供全局访问点和模组生命周期管理。

2.1 Global —— 全局访问器 核心

Global 是一个静态工具类，是获取游戏各子系统的唯一入口。所有模组代码都从这里开始。

方法作用
getSettings()获取 SettingsAPI，读写游戏配置、加载文件
getSector()获取 SectorAPI，战役星区（仅战役中可用）
getCombatEngine()获取 CombatEngineAPI，战斗引擎
getFactory()获取 FactoryAPI，创建游戏对象（仅战役中）
getSoundPlayer()获取声音播放器
getCurrentState()获取当前游戏状态（CAMPAIGN / COMBAT / TITLE）
getLogger(Class c)获取 log4j 日志器

关键静态字段：

  • LOADING_SAVE：是否正在加载存档
  • CODEX_TOOLTIP_MODE：图鉴工具提示模式

2.2 ModPlugin —— 模组插件接口

定义模组的生命周期回调。游戏会在特定时机调用这些方法。

⚠️ 官方建议

不要直接实现此接口，请继承 BaseModPlugin。

生命周期方法（按调用顺序）

方法调用时机典型用途
onApplicationLoad()所有核心加载完成、脚本编译完成后加载模组自定义数据、注册配置
onNewGame()创建新游戏时生成星区内容（替代 generators.csv）
onNewGameAfterProcGen()程序化生成完成后在程序生成基础上添加内容
onNewGameAfterEconomyLoad()经济系统加载并步进后此时 getMarket() 可返回正确市场
onNewGameAfterTimePass()新游戏初始 2 个月时间流逝后最终调整
onEnabled(boolean)模组被启用时处理模组首次启用逻辑
onGameLoad(boolean)存档加载后/新游戏创建后注册监听器、脚本，恢复运行时状态
beforeGameSave()存档保存前准备持久化数据
afterGameSave()存档保存后恢复临时状态
onGameSaveFailed()存档保存失败时回滚
onDevModeF8Reload()开发模式下按 F8 热重载后调试用

AI 选择方法

方法作用
pickShipAI(member, ship)为舰船选择 AI 实现（返回 null 用默认）
pickWeaponAutofireAI(weapon)为武器选择自动开火 AI
pickDroneAI(drone, mothership, system)为无人机选择 AI
pickMissileAI(missile, launchingShip)为导弹选择 AI

其他方法

  • configureXStream(XStream x)：配置存档序列化（XStream），注册自定义类的别名。
  • onAboutToStartGeneratingCodex() / onAboutToLinkCodexEntries() / onCodexDataGenerated()：图鉴生成相关回调。

2.3 BaseModPlugin —— 模组插件基类

实现 ModPlugin 的空实现基类。继承此类而非直接实现接口的好处：

  • 所有方法都有默认空实现，只需重写需要的方法。
  • 未来 API 新增方法时，你的模组不会因缺少实现而报错。

3.7 CampaignEventListener —— 战役事件监听器

💡 "Event" 的含义

指值得注意的事情，不仅仅是 events.json 中的事件。

内部枚举 FleetDespawnReason：

  • REACHED_DESTINATION：到达目的地（param 为 SectorEntityToken）
  • DESTROYED_BY_BATTLE：被战斗摧毁（param 为 BattleAPI）
  • NO_MEMBERS：无成员
  • PLAYER_FAR_AWAY：玩家太远
  • OTHER / NO_REASON_PROVIDED

主要回调：

  • reportPlayerOpenedMarket(market) / reportPlayerClosedMarket(market)
  • reportPlayerMarketTransaction(transaction)
  • reportBattleOccurred(winner, battle) / reportBattleFinished(winner, battle)
  • reportPlayerEngagement(result)
  • reportFleetDespawned(fleet, reason, param) / reportFleetSpawned(fleet)
  • reportFleetJumped(fleet, from, to) / reportFleetReachedEntity(fleet, entity)
  • reportPlayerReputationChange(faction, delta) / reportPlayerReputationChange(person, delta)
  • reportEconomyTick(iterIndex) / reportEconomyMonthEnd()

3.8 CampaignPlugin —— 战役插件

注册到 SectorAPI 的插件，用于自定义各类行为选择。

内部枚举 PickPriority（优先级从低到高）：

  1. CORE_GENERAL
  2. MOD_GENERAL — 模组替换核心功能
  3. CORE_SET
  4. MOD_SET — 处理一组情况（如所有丛林行星）
  5. CORE_SPECIFIC
  6. MOD_SPECIFIC — 特定遭遇
  7. HIGHEST — 绝对最高，慎用
✅ Transient 推荐

若 isTransient() 为 true，数据不存档，每次 onGameLoad() 需重新注册。推荐 transient，便于增删模组。

18.7 反射调用未公开 API

⚠️ 适用场景

SSTLib 中许多内部类和方法未公开（如 AppDriver、CampaignState、UI 内部面板等），无法直接 import。需要通过反射按名称调用。

典型情况：访问游戏内部 UI 面板、获取未公开的当前状态对象、调用 obfuscated 方法名。

核心思路（参考 LunaLib）

LunaLib 提供 ReflectionUtils 工具类，封装了基于 MethodHandles 的反射调用，并带缓存。核心 API：

方法作用
invoke(methodName, instance, vararg args)按名称调用实例方法
get(fieldName, instance)按名称读取字段
set(fieldName, instance, newValue)按名称写入字段
getField(fieldName, clazz)获取字段反射对象（可设父类递归）
getMethod(methodName, clazz)获取方法反射对象
instantiate(clazz, vararg args)调用构造器创建实例
hasMethodOfName(name, instance)检查是否含某方法（带缓存，用于 UI 爬取）
hasVariableOfName(name, instance)检查是否含某字段
getFirstDeclaredField(instance)获取第一个声明字段（适用于单字段类）

典型用法

1. 获取未公开的游戏状态对象

// AppDriver 和 CampaignState 都是未公开类，需用反射
import com.fs.state.AppDriver;
import com.fs.starfarer.campaign.CampaignState;
import lunalib.backend.util.ReflectionUtils;

var state = AppDriver.getInstance().currentState;
if (state instanceof CampaignState) {
    // getCore() 是未公开方法
    var core = ReflectionUtils.invoke("getCore", state);
    // getEncounterDialog() 也是未公开方法
    var dialog = ReflectionUtils.invoke("getEncounterDialog", state);
}

2. 访问内部 UI 面板（UI 爬取）

// 从核心 UI 获取 Refit 面板，再逐层爬取子面板
var core = ReflectionUtils.invoke("getCore", state);
if (core instanceof UIPanelAPI) {
    // getCurrentTab 是未公开方法
    var refitTab = ReflectionUtils.invoke("getCurrentTab", core) as UIPanelAPI?;

    // 通过方法名识别目标子面板
    var child = refitTab.getChildrenCopy().find {
        ReflectionUtils.hasMethodOfName("syncWithCurrentVariant", it)
    };

    if (child instanceof UIPanelAPI) {
        var member = ReflectionUtils.invoke("getMember", child);
        var shipDisplay = ReflectionUtils.invoke("getShipDisplay", child);
        var variant = ReflectionUtils.invoke("getCurrentVariant", shipDisplay);
    }
}

3. 调用未公开方法（带容错）

// 游戏版本不同方法签名可能变化，需 try-catch 回退
try {
    ReflectionUtils.invoke("syncWithCurrentVariant", child, true);
} catch (Throwable e) {
    try {
        ReflectionUtils.invoke("syncWithCurrentVariant", child);
    } catch (Throwable e2) {
        Global.getLogger(MyClass.class).error("sync failed", e2);
    }
}

4. 读取/修改私有字段

// 读取标题屏的 dialogType 字段判断是否在对话框中
var titlescreen = (TitleScreenState) AppDriver.getInstance().currentState;
var dialogActive = ReflectionUtils.get("dialogType", titlescreen);

// 修改私有字段
ReflectionUtils.set("someField", instance, newValue);

5. 扩展 UI 接口（Kotlin 扩展函数）

// UIPanelAPI 本身没有 getChildrenCopy，用反射扩展
private fun UIPanelAPI.getChildrenCopy(): List<UIComponentAPI> {
    return ReflectionUtils.invoke("getChildrenCopy", this) as List<UIComponentAPI>;
}

实现要点（参考 LunaLib ReflectionUtils.kt）

💡 关键设计

1. 用 MethodHandles 而非 Method.invoke：性能更高，且能绕过部分访问限制。

2. 反射对象本身也用反射获取：通过 Class.forName("java.lang.reflect.Field") + MethodHandles.lookup().findVirtual(...) 拿到 Field.set / Field.get 的句柄，避免直接 import 反射类。

3. 缓存反射结果：用 HashMap 缓存 ReflectedField / ReflectedMethod，键为 (类, 名称, 类型) 三元组。反射查找一次后后续调用走缓存。

4. 同时搜索 public 和 declared：clazz.fields + clazz.declaredFields，clazz.methods + clazz.declaredMethods，覆盖私有成员。

5. UI 爬取时用名称缓存：hasMethodOfName / hasVariableOfName 把每个类的成员名集合缓存下来，避免每帧重复反射。

🔑 绕过游戏安全限制（关键技术）

⚠️ 安全限制

游戏的脚本类加载器会抛出 SecurityException: File access and reflection are not allowed to scripts. 阻止直接使用 java.lang.reflect.Method 和 java.lang.reflect.Field。

关键：限制发生在类加载时，任何代码中声明这些类型（作为变量、参数、返回值）都会触发 SecurityException，即使从未调用。

✅ LunaLib 的解决方案

完全不引用 java.lang.reflect.Method 或 Field 类型，使用 Class.forName() + MethodHandles：

// 1. 用 Class.forName 获取反射类的 Class 对象，而不是直接 import
Class fieldClass = Class.forName("java.lang.reflect.Field", false, Class.class.getClassLoader());
Class methodClass = Class.forName("java.lang.reflect.Method", false, Class.class.getClassLoader());

// 2. 创建 MethodHandle 用于调用 Field/Method 的方法
MethodHandle setFieldHandle = MethodHandles.lookup().findVirtual(fieldClass, "set",
        MethodType.methodType(Void.TYPE, Object.class, Object.class));
MethodHandle getFieldHandle = MethodHandles.lookup().findVirtual(fieldClass, "get",
        MethodType.methodType(Object.class, Object.class));
MethodHandle invokeMethodHandle = MethodHandles.lookup().findVirtual(methodClass, "invoke",
        MethodType.methodType(Object.class, Object.class, Object[].class));

// 3. 所有反射对象当作 Object 处理，通过 MethodHandle 调用
Object field = clazz.getDeclaredFields()[0];  // 返回 Object，不是 Field
setFieldHandle.invoke(field, instance, value); // 通过 MethodHandle 调用 Field.set
❌ 常见错误写法（会触发 SecurityException）

以下写法直接声明了 java.lang.reflect.Method 或 Field 类型，类加载时即被脚本类加载器拦截：

// ❌ 错误：直接 import 反射类
import java.lang.reflect.Method;  // 类加载即抛 SecurityException
import java.lang.reflect.Field;

// ❌ 错误：声明 Method/Field 类型的变量
Method targetMethod = clazz.getMethod("getCore");  // 触发 SecurityException
Field f = clazz.getDeclaredField("core");           // 触发 SecurityException

// ❌ 错误：使用 IMPL_LOOKUP（IMPL_LOOKUP 字段本身需要反射获取，同样被拦截）
Field lookupField = MethodHandles.Lookup.class.getDeclaredField("IMPL_LOOKUP");

// ❌ 错误：直接调用 getMethods() 返回 Method[]（类型引用触发拦截）
Method[] methods = clazz.getMethods();

Java 版 ReflectionUtils 完整模板（ChineseInputFix 实际实现）

✅ 正确写法：完全不引用 Method/Field 类型

核心思想：用 Class.forName() 获取反射类的 Class 对象，用 MethodHandles.lookup().findVirtual() 创建 MethodHandle，所有反射对象一律当作 Object 处理。

package org.myname.mymod;

import com.fs.starfarer.api.Global;
import java.lang.invoke.MethodHandle;
import java.lang.invoke.MethodHandles;
import java.lang.invoke.MethodType;
import java.util.*;

public class ReflectionUtils {

    // 反射类的 Class 对象（用 Class.forName 获取，不直接 import）
    private static final Class<?> methodClass;
    private static final Class<?> fieldClass;

    // MethodHandle 用于调用 Method/Field 的方法（避免直接引用类型）
    private static final MethodHandle invokeMethodHandle;
    private static final MethodHandle getMethodNameHandle;
    private static final MethodHandle getMethodParametersHandle;
    private static final MethodHandle setFieldAccessibleHandle;
    private static final MethodHandle getFieldHandle;
    private static final MethodHandle getFieldNameHandle;

    // 缓存：类 -> (方法签名 -> Method 对象)
    private static final Map<Class<?>, Map<String, Object>> methodCache = new HashMap<>();
    private static final Map<Class<?>, Map<String, Object>> fieldCache = new HashMap<>();

    static {
        try {
            // 1. 用 Class.forName 获取反射类的 Class 对象
            ClassLoader jdkLoader = Class.class.getClassLoader();
            methodClass = Class.forName("java.lang.reflect.Method", false, jdkLoader);
            fieldClass = Class.forName("java.lang.reflect.Field", false, jdkLoader);

            // 2. 创建 MethodHandle 用于调用 Method/Field 的方法
            invokeMethodHandle = MethodHandles.lookup().findVirtual(methodClass, "invoke",
                    MethodType.methodType(Object.class, Object.class, Object[].class));
            getMethodNameHandle = MethodHandles.lookup().findVirtual(methodClass, "getName",
                    MethodType.methodType(String.class));
            getMethodParametersHandle = MethodHandles.lookup().findVirtual(methodClass, "getParameterTypes",
                    MethodType.methodType(Class[].class));

            setFieldAccessibleHandle = MethodHandles.lookup().findVirtual(fieldClass, "setAccessible",
                    MethodType.methodType(void.class, boolean.class));
            getFieldHandle = MethodHandles.lookup().findVirtual(fieldClass, "get",
                    MethodType.methodType(Object.class, Object.class));
            getFieldNameHandle = MethodHandles.lookup().findVirtual(fieldClass, "getName",
                    MethodType.methodType(String.class));
        } catch (Throwable e) {
            throw new RuntimeException("ReflectionUtils 初始化失败", e);
        }
    }

    // 3. 所有反射对象当作 Object 处理，通过 MethodHandle 调用
    public static Object invoke(Object obj, String methodName, Object... args) {
        if (obj == null || methodName == null) return null;
        try {
            Class<?> clazz = obj.getClass();
            Object method = findMethod(clazz, methodName, args.length);
            if (method != null) {
                return invokeMethodHandle.invoke(method, obj, args);
            }
        } catch (Throwable e) {
        }
        return null;
    }

    public static Object get(Object obj, String fieldName) {
        if (obj == null || fieldName == null) return null;
        try {
            Class<?> clazz = obj.getClass();
            Object field = findField(clazz, fieldName);
            if (field != null) {
                return getFieldHandle.invoke(field, obj);
            }
        } catch (Throwable e) {
        }
        return null;
    }

    // 4. 查找方法：返回 Object，不是 Method
    private static Object findMethod(Class<?> clazz, String methodName, int paramCount) {
        Map<String, Object> cache = methodCache.computeIfAbsent(clazz, k -> new HashMap<>());
        String key = methodName + ":" + paramCount;

        return cache.computeIfAbsent(key, k -> {
            try {
                // getMethods() 返回 Object[]，不是 Method[]
                Set<Object> methods = new HashSet<>();
                methods.addAll(Arrays.asList((Object[]) clazz.getMethods()));
                methods.addAll(Arrays.asList((Object[]) clazz.getDeclaredMethods()));

                for (Object method : methods) {
                    String name = (String) getMethodNameHandle.invoke(method);
                    if (!name.equals(methodName)) continue;
                    Class<?>[] params = (Class<?>[]) getMethodParametersHandle.invoke(method);
                    if (params.length != paramCount) continue;
                    return method;  // 返回 Object
                }
            } catch (Throwable e) {
            }
            return null;
        });
    }

    // 5. 查找字段：返回 Object，不是 Field
    private static Object findField(Class<?> clazz, String fieldName) {
        Map<String, Object> cache = fieldCache.computeIfAbsent(clazz, k -> new HashMap<>());
        return cache.computeIfAbsent(fieldName, k -> {
            try {
                for (Object field : (Object[]) clazz.getDeclaredFields()) {
                    String name = (String) getFieldNameHandle.invoke(field);
                    if (name.equals(fieldName)) {
                        setFieldAccessibleHandle.invoke(field, true);
                        return field;  // 返回 Object
                    }
                }
            } catch (Throwable e) {
            }
            return null;
        });
    }
}

⚠️ UI 遍历的额外陷阱

不要直接调用 getMethods() 遍历方法名：虽然 getMethods() 本身返回 Object[] 不会触发 SecurityException，但在某些游戏版本中仍可能被拦截。

解决方案：使用预定义的 getter 方法名称列表，通过 ReflectionUtils.invoke(obj, methodName) 逐个尝试调用，避免枚举所有方法。

// ❌ 错误：遍历 getMethods() 可能触发 SecurityException
for (Object m : (Object[]) clazz.getMethods()) {
    String name = (String) getMethodNameHandle.invoke(m);
    // ...
}

// ✅ 正确：预定义方法名列表，逐个尝试
String[] entryMethods = {
    "getCurrentDialog", "getCore", "getCurrentPanel",
    "getInteractionDialog", "getDialog", "getCurrentCore",
    "getRootPanel", "getCurrentInteractionDialog"
};
for (String methodName : entryMethods) {
    try {
        Object result = ReflectionUtils.invoke(campaignUI, methodName);
        if (result != null && isValidUIObject(result)) {
            // 处理 result
        }
    } catch (Exception e) {
    }
}
⚠️ 注意事项

版本兼容：未公开方法名可能随游戏版本变化（尤其 obfuscated 名），需做容错。

性能：反射调用比直接调用慢，避免在每帧高频路径使用，务必带缓存。

稳定性：反射破坏封装，游戏更新可能导致字段/方法消失而报错。

优先公开 API：能用 Global / SectorAPI 等公开接口实现的，不要用反射。

18.8 调度器模式：在主菜单注册监听器

⚠️ 适用场景

SSTLib 生命周期回调存在时间差问题：

· onApplicationLoad 在游戏最早期触发，此时 Global.getSector() 为 null，Global.getCurrentState() 还不是 TITLE/CAMPAIGN，直接注册监听器会 NPE。

· onGameLoad 只在读档时触发，主菜单阶段不会调用。若需要在主菜单就挂上监听器（如全局输入修复、主菜单 UI 注入），这两者都不够用。

核心思路

用 ScheduledExecutorService 在后台轮询 Global.getCurrentState()，一旦进入目标状态（TITLE/CAMPAIGN/COMBAT）就注册监听器并 shutdown() 调度器——不依赖读档，主菜单即可挂载。

💡 关键点

轮询条件：Global.getCurrentState() == GameState.TITLE（主菜单）或 CAMPAIGN（战役），表明游戏核心已就绪。

一次性：注册成功后立即 scheduler.shutdown()，避免重复注册和线程泄漏。

容错：catch 异常也要 shutdown，防止调度器空转。

完整模板

package org.myname.mymod;

import com.fs.starfarer.api.BaseModPlugin;
import com.fs.starfarer.api.GameState;
import com.fs.starfarer.api.Global;
import java.util.concurrent.*;

public class MyModPlugin extends BaseModPlugin {

    private ScheduledExecutorService scheduler;

    @Override
    public void onApplicationLoad() throws Exception {
        super.onApplicationLoad();
        // 应用启动即开始轮询，主菜单就绪后注册
        startSchedulerAndRegister();
    }

    @Override
    public void onGameLoad(boolean newGame) {
        super.onGameLoad(newGame);
        // 读档兜底：若调度器仍未注册成功（如主菜单未触发），此处补注册
        startSchedulerAndRegister();
    }

    /**
     * 启动调度器，等待游戏进入 TITLE/CAMPAIGN 后注册监听器
     */
    private void startSchedulerAndRegister() {
        // 避免重复启动：若已有调度器在跑，先关掉
        if (scheduler != null) {
            scheduler.shutdownNow();
        }
        scheduler = Executors.newSingleThreadScheduledExecutor();
        scheduler.scheduleAtFixedRate(() -> {
            try {
                GameState state = Global.getCurrentState();
                if (state == GameState.TITLE || state == GameState.CAMPAIGN || state == GameState.COMBAT) {
                    registerListeners();
                    scheduler.shutdown();
                }
            } catch (Exception e) {
                Global.getLogger(MyModPlugin.class).error("注册监听器出错", e);
                scheduler.shutdown();
            }
        }, 0, 100, TimeUnit.MILLISECONDS);
    }

    /**
     * 实际注册逻辑（此时游戏核心已就绪）
     */
    private void registerListeners() {
        if (Global.getSector() != null) {
            Global.getSector().addListener(new MyListener());
            Global.getSector().addScript(new MyEveryFrameScript());
        }
        // 注意：Global.getCombatEngine() 仅在战斗中非 null，不要在主菜单用它注册
    }
}

状态判断对照

GameState含义可用对象
TITLE主菜单 / 标题屏Global.getSector() 可能为 null；需用反射访问主菜单 UI
CAMPAIGN战役（星图）Global.getSector() 非 null，可注册监听器/脚本
COMBAT战斗Global.getCombatEngine() 非 null，可注册战斗插件
⚠️ 常见陷阱

1. 调度器字段复用导致泄漏：waitLoadFinished() 和 startSectorCheckThread() 共用同一个 scheduler 字段时，后者会覆盖前者引用，前者若未主动 shutdown 会一直空转。解决：启动新调度器前 if (scheduler != null) scheduler.shutdownNow();。

2. 重复注册：onApplicationLoad 启动调度器后，onGameLoad 又启动一次，可能注册两份监听器。解决：用标志位或先 shutdown 旧调度器。

3. 主菜单用战斗引擎：Global.getCombatEngine().addPlugin(...) 在 TITLE 阶段 getCombatEngine() 为 null，会 NPE。主菜单阶段应走 Global.getSector().addListener() 或反射挂到主菜单 UI。

4. 线程安全：调度器在后台线程执行，访问游戏对象时注意 SSTLib 并非完全线程安全，注册动作最好尽快完成并退出。
